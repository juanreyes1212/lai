The MDX migration a few months back replaced `MarkdownRenderer` on
every blog post — except nobody deleted the file. The component sat
there, exported from nowhere but still imported through the module
graph indirectly by TypeScript path completion, keeping
`react-markdown` and `remark-gfm` alive in the runtime bundle.

## The audit

```bash
rg -l "MarkdownRenderer" src
# → src/components/MarkdownRenderer.tsx  (self-reference)
# → src/content/blog/*.mdx               (historical prose)
```

One file, self-referential. Safe to delete. `react-markdown` came off
`package.json` in the same commit.

## Why "unused" doesn't mean "harmless"

Tree-shaking is optimistic, not omniscient. The moment a file has a
top-level side effect — a `document.` reference, a `console.log`, a
polyfill import — the bundler keeps it. Deleting the whole file is
the only reliable signal.

## The rule going forward

Any migration ends with a `git rm` of the thing being migrated
*from*. Not later, not "when we're sure" — in the same PR.

Cheapest 200 KB I've ever shipped.
